# riot
A urfav CLI server which provides:
MCP - model context protocol
GQL - graphql service
US - a web based user interface

## data
uses `phi`

## structure
`go.mod`        : yes, this is a golang app
`./cmd/`        : command-line interface using urfav
`./internal/`
  - `/gql/`    : graphql server
  - `/mcp/`    : model context protocol server
  - `/orm/`    : `phi` database client
  - `/schema/` : prisma data schema for phi
  - `/utils/`  : handy utilities for this app
  - `/web/`    : web ui, very javascript heavy (no react).

## web ui sections

Three sibling UIs are mounted on the one port, each with its own route, its own
`New<Name>WebService()` in `internal/web/`, and its own script and stylesheet
paths so they never collide on `/scripts/` and `/styles/`. The nav bar lists
them in this order: **projects, agents, skills**.

| route | service | left column | right column |
|---|---|---|---|
| `/projects/` | `NewProjectsWebService` | projects, excluding `all` | the focused project's agents, or `all`'s when none is focused |
| `/agents/` | `NewAgentsWebService` | agents | the selected agent's skill tree |
| `/skills/` | `NewWebService` | skills | the skill chooser and graph |

### the projects tree depth

The projects tree renders an agent, its bound skills, their dependencies, and
those dependencies' dependencies — three skill levels — and stops. The GraphQL
fragment asks for exactly two levels of `dependencies` nesting, so the data and
the drawing agree; a deeper fragment would fetch rows the tree never draws.

`all` is a real project row in the registry but is never listed in the left
column: it is the fallback the right column shows when no project is focused.
`?project=all` therefore resolves to the unfocused view, not to a focused
project named `all`.

### project identity

A project's `name` is its primary key, so `SaveProject` never renames a record: an update addresses the row by the name it already has and rewrites only `location`, `skillsPath` and `agentsPath`.
`isNew` selects create over update; a create whose name already exists surfaces the store's unique-constraint error unchanged so the browser can show it.
